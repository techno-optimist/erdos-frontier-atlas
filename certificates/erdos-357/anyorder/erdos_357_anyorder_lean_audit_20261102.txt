6. STATEMENT AUDIT  (S: did not fire)   (most important)
  The target, in plain words:
    k, N natural numbers; x : Fin k -> N is a row x_0, ..., x_{k-1} in this fixed order (any order allowed, no monotonicity);
    hinj:    the entries are distinct;
    hrange:  each entry lies in 1..N;
    hblocks: for u <= v and u' <= v', if sum_{i in [u, v]} x_i = sum_{i in [u', v']} x_i, then (u, v) = (u', v').
             So every consecutive block (all lengths together) is determined by its sum, which is exactly "all
             consecutive-block sums are distinct". Finset.Icc u v on Fin k is the closed index interval, nonempty when u <= v.
    hk:      10^22 <= k;
    conclusion: (3/2 + 1/10^10) * k < N, in the reals.
  Judgment: the statement faithfully says "if k distinct integers from 1..N, in this order, have all consecutive block sums
  distinct, and k >= 10^22, then N > (3/2 + 10^-10) k". That is a(k) > (3/2 + 10^-10)k for A364153 when k >= 10^22.
  (hinj is implied by hblocks via length-1 blocks, so including it is harmless.)
  Non-vacuity, machine-checked (audit/Witness.lean, rc 0, 19.5 s, kernel `decide`, no native_decide; axioms standard three):
  - witness_satisfies_hypotheses: x = 4 1 2 10 22 15 21 24 28 29 27 16 26 20 18 23 25 19 11 (k = 19, N = 29) satisfies
    hinj, hrange and hblocks exactly as written in the target. Only hk fails, as it must at k = 19.
  - hblocks_rejects_bad_row: the row 1,2,3 (where [1,2] and [3] both sum to 3) fails hblocks, so the hypothesis has teeth.
  - For every k the hypotheses can hold (argued, not formalized): x_i = 2^i with N = 2^k gives block sums 2^(v+1) - 2^u,
    which are all distinct. So the theorem is not vacuous at k >= 10^22. It genuinely rules out every row with N <= (3/2 + 10^-10)k.
  Definitions in Basic.lean are not trivialized:
  - block a r i = sum_{j<r} a(i+j).
  - extend x is x on indices below k and 0 elsewhere.
  - Admissible keeps positivity, bounds, injectivity and full block-sum injectivity (any lengths r, s with i+r <= k, j+s <= k).
  - admissible_extend derives Admissible from exactly the target's hypotheses, through block_as_fin_Icc (the range-sum
    equals the Fin Icc sum). This bridge is checked in Lean, not assumed. The final theorem uses only `Admissible`, hk and the
    by_contra assumption N <= (3/2 + 10^-10)k.

9. CAVEATS / OPEN ITEMS
  - The argument and the formalization are both AI-written (GPT Astra, prompted by Kevin Russell). Review so far is
    AI-only: Ford's audit plus one outside model reading. No human expert has reviewed it, and it is not refereed.
  - A clean kernel check means the Lean theorem follows from Mathlib's axioms. It does not tell us whether the
    result is new. The novelty search found no earlier any-order improvement on Hegyvári (1986), but the search is not
    exhaustive. The erdosproblems.ai page states a larger any-order bound that appears to come from an increasing-order
    paper. Any write-up has to handle that respectfully.
  - The gain is tiny (10^-10 in the constant) and applies only for k >= 10^22. It says nothing about any computed
    value of A364153; all 19 known values lie far outside its range.
  - Trust base: Lean 4.33.1, Mathlib 0df444a3 and their axioms. The commit hashes a1d0674 / e5e5e75 are as claimed but
    unverified (no git metadata in the zip); the zip sha256 is the pin.
  - The independent-kernel export covers erdos357_any_order_improvement and its dependency closure. The audit-only
    files (Witness, CrossCheck) were checked by Lean's elaborator and kernel, not by nanoda or con-ron.
  - nanoda and con-ron binaries are the same builds used for the Paper II audit. lean4export was rebuilt at tag v4.33.0
    with the toolchain set to v4.33.1, so it reads these .olean files.
  - Nothing was published, posted or opened as a PR.
